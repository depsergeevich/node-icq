# node-icq-server
Самостоятельный ICQ-сервер на чистом JavaScript. Реализует протокол OSCAR (FLAP/SNAC/TLV),
аутентификацию, контакт-лист SSI, обмен сообщениями и анкеты White Pages.

## Возможности

### Ядро протокола
- **Двойная аутентификация** — MD5 (BUCP) и XOR Roasting
- **FLAP/SNAC/TLV** — полная бинарная реализация
- **Защита соединения** — ведра токенов на пакеты и байты, проверка длины кадра
  до выделения памяти, таймаут неактивности, лимит попыток входа по паре (IP + UIN)

### Обмен сообщениями
- **Канал 1** — текстовые сообщения (ASCII, UTF-8, UTF-16, CP1251)
- **Канал 2** — Rendezvous / Extended
- **Канал 4** — старый формат ICQ
- **ACK сообщений** — подтверждение доставки
- **Офлайн-сообщения** — с ограничением очереди (по умолчанию 200 на адресата) и сроком жизни 30 дней

### Контакты и присутствие
- **SSI (Server-Side Information)** — полное управление списком контактов
  - добавление / изменение / удаление контактов и групп
  - хранение в SQLite
  - обработка SSI Activate
  - SSI Check с оптимизацией «нет изменений»
- **Статусы контактов** — уведомления онлайн/офлайн в реальном времени
- **Стандартные статусы** — Online, Away, DND, NA, Occupied, Free for Chat, Invisible
- **X-Status** — Angry, Depression, At Home, At Work и прочие
- **Расширенные статусы** — настроение и заметки через BART (TLV 0x001D)
- **Capabilities** — сквозная передача TLV для совместимости с клиентами
- **Поиск по анкетам** — по UIN и по White Pages (QIP 2005, QIP Infium)

### Веб-панель
- Публичная регистрация (HTML + JSON API)
- Админка: онлайн-сессии, список аккаунтов, kick, системная рассылка
- ICQ HTTP API (`/auth/getChallenge`, `/auth/clientLogin`, `/aim/startOSCARSession`)
  для ICQ 7/8 и мобильных клиентов

## Установка

> [!CAUTION]
> Перед первым запуском настройте `config.js`.

```bash
git clone https://github.com/Artemchik-Development/node-icq-server.git
cd node-icq-server
npm install
node server.js
```

Требуется Node.js 18 или новее. Зависимости: `sqlite3` и `iconv-lite`.

## Управление аккаунтами

Через CLI:

```bash
node database.js add 100000 password              # UIN + пароль
node database.js add 100000 pwd Alice Smith mail  # с подробностями
node database.js auto password                    # выдать свободный UIN
node database.js passwd 100000 newpass           # смена пароля
node database.js list                             # список аккаунтов
node database.js search Alice                     # поиск
node database.js del 100000                       # удаление
node database.js nextuin                          # следующий свободный UIN
node database.js migrate                          # перевести старые пароли в хеши
node database.js schema                           # структура таблиц
```

Либо через встроенный веб-интерфейс на `http://<адрес>:8080/`.

## Как хранятся пароли

Двухслойная схема:

- `users.password` — хеш **PBKDF2-SHA256** (210 000 итераций). Это основной
  верификатор пароля.
- `users.password_secure` — **AES-256-GCM** шифротекст того же пароля.

Второй слой нужен потому, что сам протокол OSCAR требует пароль, а не его хеш:

| Механизм | Что требует |
|---|---|
| XOR Roasting | сравнение пароля напрямую |
| BUCP / MD5 | `md5(пароль)` внутри хеша |
| ICQ HTTP API | `HMAC-SHA256(пароль, challenge)` |

Ключ шифрования берётся из `ICQ_MASTER_KEY`; если переменная не задана, ключ
генерируется один раз и хранится в файле `.authkey` (права 600, добавлен в `.gitignore`).

Что это даёт: утечка только файла БД не раскрывает пароли. Утечка сервера целиком
(вместе с `.authkey`) — раскрывает, этого не избежать без отказа от XOR/MD5/HTTP API.

Чтобы отключить эскорт-слой и хранить только необратимый хеш, поставьте
`LEGACY_AUTH_ENABLED: false`. Учтите: тогда перестанут работать вход через XOR Roasting,
BUCP/MD5 и ICQ HTTP API — останется только веб-регистрация.

### Миграция со старой базы

При первом запуске пароли, сохранённые открытым текстом, автоматически
переводятся в PBKDF2 + шифротекст. Значения удаляются безвозвратно, поэтому
**сделайте резервную копию `icq.db` до первого запуска**.

## Конфигурация

Все значения живут в `config.js` и переопределяются переменными окружения
с префиксом `ICQ_` (удобно для systemd/Docker).

Ключевые параметры:

| Параметр | По умолчанию | Переменная | Описание |
|---|---|---|---|
| `HOST` | `0.0.0.0` | `ICQ_HOST` | Адрес прослушивания TCP |
| `AUTH_PORT` | `5190` | `ICQ_AUTH_PORT` | Порт сервера аутентификации |
| `BOS_PORT` | `5191` | `ICQ_BOS_PORT` | Порт BOS |
| `BOS_ADDRESS` | автоопределение | `ICQ_BOS_ADDRESS` | Адрес, который клиенту дают для подключения к BOS |
| `WEB_PORT` | `8080` | `ICQ_WEB_PORT` | Порт веб-панели |
| `HTTPS_PORT` | `443` | `ICQ_HTTPS_PORT` | Порт HTTPS |
| `ADMIN_USER` | `admin` | `ICQ_ADMIN_USER` | Логин админки |
| `ADMIN_PASS` | `changethispassword` | `ICQ_ADMIN_PASS` | Пароль админки (**смените!**) |
| `REGISTRATION_ENABLED` | `true` | `ICQ_REGISTRATION_ENABLED` | Регистрация через OSCAR и веб |
| `PBKDF2_ITERATIONS` | `210000` | `ICQ_PBKDF2_ITERATIONS` | Стоимость хеширования |
| `LEGACY_AUTH_ENABLED` | `true` | `ICQ_LEGACY_AUTH_ENABLED` | Хранить ли обратимый шифротекст пароля |
| `SESSION_IDLE_TIMEOUT_MS` | `900000` | `ICQ_SESSION_IDLE_TIMEOUT_MS` | Таймаут неактивной сессии |
| `MAX_OFFLINE_MESSAGES` | `200` | `ICQ_MAX_OFFLINE_MESSAGES` | Размер очереди офлайн-сообщений |
| `CORS_ALLOW_ORIGIN` | `null` | `ICQ_CORS_ALLOW_ORIGIN` | По умолчанию CORS закрыт |

`BOS_ADDRESS` не может быть `0.0.0.0`: это адрес прослушивания, подключиться к нему
нельзя. Если оставить поле пустым, сервер определит IP сетевого интерфейса сам.

Конфигурация проверяется при старте: ошибки (занятые порты, выключенный диапазон
UIN, слишком маленький `PBKDF2_ITERATIONS`) останавливают запуск с понятным
сообщением, предупреждения выводятся в консоль.

## Порты

| Порт | Назначение |
|---|---|
| 5190/tcp | Аутентификация (OSCAR) |
| 5191/tcp | BOS — основной сервер |
| 8080/tcp | Веб-панель и HTTP API |
| 443/tcp | HTTPS (нужны `cert.pem` и `key.pem`, требуются права на порт) |

## Безопасность при публикации в интернет

- Смените `ADMIN_PASS` или задайте `ICQ_ADMIN_PASS`.
- Не держите `DEBUG_PACKETS: true` — каждый байт трафика попадает в лог.
- Ограничьте доступ к порту 8080 (админка) firewall'ом.
- Регулярно копируйте `icq.db` **вместе с `.authkey`** — потеря ключа означает
  невозможность входа через XOR/MD5 до смены паролей.

## Структура проекта

| Файл | Назначение |
|---|---|
| `server.js` | TCP-серверы OSCAR, класс сессии, защита соединения, завершение работы |
| `auth.js` | Аутентификация (XOR/BUCP), регистрация, выдача cookie |
| `bos.js` | Логика BOS: SSI, сообщения, статусы, анкеты, поиск |
| `database.js` | SQLite, хеширование паролей, CLI |
| `web.js` | Веб-панель, админка, ICQ HTTP API |
| `oscar.js` | Сборка и разбор FLAP/SNAC/TLV |
| `security.js` | PBKDF2, AES-256-GCM, мастер-ключ, сравнение за постоянное время |
| `ratelimit.js` | Ведра токенов для ограничения нагрузки |
| `utils.js` | Отладочный hex-дамп пакетов |
